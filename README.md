# output-only-final

一份给 AI Agent 的 SKILL。让所有交付物只呈现最终结果，不写它如何变成这样的过程，也不写只有看过这次对话才看得懂的内容。

适用范围：凡是产出或修改将被用户、读者、审稿人查看的文件——网页、UI、报告、论文、PPT、PDF、Word、Excel、README、代码与注释、截图、邮件、导出文件、提交信息。

## 两条规则

**一、交付物只对最终形态负责，不写它如何变成这样的过程。**
用户和 AI 谈了多少轮、改了多少版、排错经过、踩过的坑、总结的教训、AI 的思考过程、方案取舍、验证结果、下一步打算——这些属于“怎么变成这样的过程”，一律不写进交付物（要告诉用户就写到聊天里）。

**二、看交付物的人不知道有过这次对话，对话内容一无所知。**
“你之前问的问题”“根据您的要求”“如前所述我们”“为满足需求文档第 4 条”、引用对话原话作答、移植项目里讲“原版怎么样”——这些依赖对话才能看懂，一律改写或删掉。

写完之后把自己当成第一次看到这份东西的最终用户、读者或审稿人通读一遍，凡是让人觉得“这是一个人与AI对话后做出来的，而我不知道该对话的内容”或“这是在告诉我它怎么做出来的”，删掉或改成只说结果。

## 该保留的体裁内容

有些东西看起来像过程，其实是体裁本身要的，要写、要写够：论文的方法学、Limitations、Future Work；代码注释里一两句解释非显然约束的“为什么”；移植项目一句话的兼容性事实；项目在维护的 CHANGELOG。判断标准：写给产物的读者用，且即使没有这次对话、没有 AI 参与，专业团队做这份东西时它也会在。

用户明确要求把过程写进交付物时（比如要求文档记录设计决策、要求界面加说明文案、要求提交信息交代改动），按要求写。没要求时，从严。
